Guia de Branches e Pull Requests — Projeto GymLeague

#-----------------------------------------------------------------------------------------------------#

1. Sincronizar a branch principal
   git checkout main
   git pull origin main

   Mantenha sempre a branch local atualizada antes de iniciar uma tarefa para evitar conflitos futuros.

#-----------------------------------------------------------------------------------------------------#

2. Criar uma branch descritiva para a tarefa
   Formato sugerido:
   - feature/<descricao-curta> para novas funcionalidades
   - fix/<descricao-curta> para correções

   Exemplo:
   git checkout -b feature/landing-header-responsivo

#-----------------------------------------------------------------------------------------------------#

3. Desenvolver e acompanhar mudanças
   - Implemente a tarefa.
   - Use git status para revisar o que foi alterado.
   - Rode verificações locais sempre que possível (ex.: npm run lint, flask --app app.py --help).

#-----------------------------------------------------------------------------------------------------#

4. Preparar e criar o commit
   git add caminho/do/arquivo
   git commit -m "Landing: ajusta header responsivo"

   Dicas:
   - Commits pequenos e focados facilitam a revisão.
   - Utilize mensagens claras indicando o módulo impactado.

#-----------------------------------------------------------------------------------------------------#

5. Enviar a branch para o repositório remoto
   git push -u origin feature/landing-header-responsivo

#-----------------------------------------------------------------------------------------------------#

6. Abrir o Pull Request
   - No GitHub, crie um PR de sua branch para main.
   - Descreva o contexto, os arquivos principais e se há passos de teste.
   - Vincule à tarefa correspondente (quando houver).

#-----------------------------------------------------------------------------------------------------#

7. Revisão e merge
   - Aguarde pelo menos uma revisão de outro membro.
   - Resolva comentários e conflitos, se existirem.
   - Após aprovação, conclua o merge via GitHub.

#-----------------------------------------------------------------------------------------------------#

8. Atualizar o ambiente local após o merge
   git checkout main
   git pull origin main
   git branch -d feature/landing-header-responsivo   (opcional para remover a branch local já mesclada)

#-----------------------------------------------------------------------------------------------------#
